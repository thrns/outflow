## Implementation summary

`outflow-settings::save_settings_atomic(path, settings)` validates settings before filesystem operations and serializes through the existing schema v1 codec. On Unix it rejects missing/invalid parents, symlink destinations, and non-regular destinations; creates an exclusive, uniquely named same-directory temp file with mode `0600`; writes, flushes, and synchronizes it; then atomically renames it over the destination and synchronizes the parent directory. It never removes the destination before rename. Pre-replacement errors preserve old contents and clean the temp file. A parent-directory sync failure after rename returns `ReplacementDurabilityUncertain` because the replacement is already visible.

Errors store no path or operating-system error text and do not include JSON, shortcut, or vocabulary values. Test-only hooks simulate partial write, permission denial, file-sync, pre-replacement, and post-replacement directory-sync failures without filling the disk. No runtime dependency or lockfile change was introduced. The example and tests use temporary directories, synthetic settings, and no Outflow user configuration path.

## Failure scenarios covered

- Invalid settings and unsupported schema versions leave an existing file untouched.
- Simulated partial write, permission denial, file synchronization failure, and pre-replacement interruption preserve the old file and remove the temporary file.
- Simulated parent-directory synchronization failure is reported after replacement; the new JSON is present and valid, and there is no temp file.
- Missing and non-directory parent paths return distinct errors.
- Directory and symbolic-link destinations are rejected; the symlink target remains unchanged.
- The resulting Unix file mode is exactly `0600` on the tested filesystem.
- Error rendering does not include synthetic private configuration markers.

## Explicit-path settings file loading — 2026-10-30

**Scope:** Task 9, the read-only loader addition to the existing T-018 storage work. The loader takes only a caller-supplied path and returns `Result<Option<Settings>, SettingsStorageError>`. A missing file returns `Ok(None)` without creating anything. Existing files are checked as regular non-symlink files, read-only, capped at 1 MiB, decoded as UTF-8, and validated through `Settings::from_json()`.
