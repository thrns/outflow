# T-017 settings schema v1 and JSON codec handoff

## Implemented

- Kept the existing public Settings data model, defaults, and validation rules.
- Added exact dependencies `serde = 1.0.229` with `derive` and `serde_json = 1.0.154`; updated `Cargo.lock` with their transitive packages.
- Added `Settings::to_json()` and `Settings::from_json(&str)`. Encoding validates first. Decoding rejects malformed JSON, unsupported versions, invalid settings, missing required fields, and unknown fields, then runs the existing validator.
- Added Serde support to the public settings types. Cleanup modes use `clean` and `verbatim`; absent shortcuts serialize as `null` but their keys remain required during decoding. The Rust input-device `None` value serializes as the documented `system-default` string.
- Kept codec errors content-free: parse errors contain only line and column; validation errors use the existing safe SettingsError messages. No raw JSON, vocabulary, or shortcut values are logged or embedded.
- Added `crates/settings/examples/json_roundtrip.rs` and 15 codec tests. The existing 15 settings tests and 2 core tests remain passing.
- Updated README instructions and JSON verification results. No frontend, root workspace manifest, `docs/TASKS.md`, or UI files changed.
